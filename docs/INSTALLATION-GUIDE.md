# ITD Cookies — установка

Основание: опубликованный официальный v0.4.4, реальное локальное native updater acceptance PASS и [feasibility audit](https://github.com/itdream24/itd-cookies/blob/4bc5fa007a1c2bd836bf10db009a080126c1c47f/docs/ITD-COOKIES-WP50-FEASIBILITY.md).
Это инструкция для будущего согласованного rollout; установка на production
в рамках исследования не выполнялась.

## До установки

### Изменение 0.4.5 — Smart Consent Categories

Окно и динамическая Cookie Policy показывают только используемые категории из
реестра сервисов; Necessary остаётся всегда. При отсутствии необязательных
сервисов баннер содержит одну кнопку подтверждения. Оформление 0.4.4 сохранено.
Новые выборы не разрешают отсутствующие категории. Отдельная first-party cookie
`itd_cookies_services` хранит идентификаторы состава сервисов, известного при
выборе, с тем же сроком, что и schema 1 cookie согласия. Старый Reject сохраняется;
старое положительное согласие и legacy ModuBricks требуют явного подтверждения.
Новый сервис или изменённый provider ID не наследует прежний Accept all.
При изменении поставщика/назначения под прежним ID внешней интеграции обновляйте
`consent_revision` в реестре/Script Adapter или общую версию согласия. Внутренние
изменения GTM контейнера плагин автоматически не определяет.
После установки и изменения состава сервисов очистите page/asset cache.
Зарегистрируйте site-wide описания сервисов для полной site-wide политики;
условные группы описывают свою страницу. Для CSP учитывайте финальную локализацию
контроллера после регистрации групп. Подробности: `SCRIPT-ADAPTERS.md` и
`ITD-COOKIES-0.4.5-CONSENT-DECISION.md`. Карты по-прежнему независимы от Analytics.

1. На отдельном staging проверьте версии Core/PHP. Header 0.4.4 заявляет
   WP 5.2+, PHP 7.4+, но официальная совместимость Core с PHP 7.4 начинается
   с WP 5.3. PHP 7.3/7.4 EOL; для новых сайтов выбирайте актуальные Core и
   PHP с security support. WP 5.0 не является принятой поддержкой плагина.
2. Составьте список consent/analytics plugins, MU plugins, theme snippets,
   GTM tags, внешних script injections и кеширования. Определите владельца
   каждого SDK. Отключите дублирующие tracking snippets на staging и убедитесь,
   что тот же сервис не установлен одновременно нативно, в GTM и через adapter.
   Перед удалением snippets сохраните исходный код/настройки для rollback.
3. Сохраните файлы сайта, БД, plugin settings/active_plugins, policy pages и
   конфигурацию theme/cache. Проверьте Restore на отдельном сайте. Резервные
   копии, HAR, cookies и credentials храните вне web-root и Git.
4. При миграции ModuBricks сохраните его настройки и деактивируйте его consent
   engine перед включением ITD Cookies. Два consent engine вместе не поддержаны.

## Установка и настройка

1. Скачайте построенный asset itd-cookies-0.4.4.zip и checksum из
   [официального Release](https://github.com/itdream24/itd-cookies/releases/tag/v0.4.4).
   Source code ZIP GitHub не является installable production package.
2. Проверьте SHA-256: 4f4e0e9a98baeef087559e3863251b6f5f56cf3d427eb11566cfeba2872c53fe.
   В архиве один root itd-cookies/, main file, local assets и ru_RU translations;
   tests/docs/vendor/node_modules отсутствуют.
3. Plugins → Add New → Upload Plugin → Install → Activate. Для уже установленной
   копии используйте native updater. Upload/Replace имеется только в WP >=5.5;
   older Core assisted procedure — [rollback playbook](ROLLBACK-PLAYBOOK.md).
4. Settings → ITD Cookies: включите баннер, задайте заголовок/описание, один из
   пяти размеров, срок consent и version политики. Не меняйте consent version
   без содержательной причины: это заставляет посетителя выбирать снова.
5. Укажите HTTPS или относительные legal URLs. Абсолютный HTTP своего сайта
   преобразуется в относительный адрес; внешний HTTP отклоняется с ошибкой,
   прежнее валидное значение сохраняется. Проверьте фактически сохранённые URL.
6. Создайте Cookie Policy явной admin кнопкой и проверьте содержание вручную.
   При наличии существующей policy не заменяйте её без решения владельца.
7. Необходимые cookies always on; Functional/Analytics/Marketing — по выбору.
   Включайте только нужные провайдеры с корректными ID. Yandex/GA4/GTM/Clarity
   относятся к Analytics, Meta — к Marketing. Настройки тегов внутри GTM
   должен согласовать владелец контейнера; ITD не переписывает их автоматически.
8. Shortcodes: [itd_cookies_settings], [itd_cookies_policy],
   [itd_cookies_legal_links]. При желании включите отдельный legal footer.

## UX версии 0.4.4

- Пять размеров окна используют локальную базу 16 px и коэффициенты
  80/90/100/115/130%. Стандартный текст описания/кнопок — 15 px,
  заголовок — 20 px, ссылки — 14 px. Гарнитура наследуется от темы.
  Размеры теперь независимы от theme root font-size; на старых темах
  внешний вид «Стандартного» может измениться. Browser zoom сохраняется.
- Автоматический footer по-прежнему выключен по умолчанию. Если включён,
  ссылки центрируются; настройка позволяет выбрать слева/по центру/справа.
  На узких экранах элементы переносятся, область клика не меньше 44 px.
- Для собственного оформленного футера отключите автоматический вывод
  и разместите `[itd_cookies_legal_links]` либо `[itd_cookies_settings]`
  вручную. Выравнивание автоматического блока не меняет shortcode-контейнер.
- Информационная подсказка Analytics объясняет независимые запросы карт.
  Она не блокирует карты и не подтверждает юридическое соответствие.

## Встроенные Яндекс.Карты — принятое правило проектов

Существующие iframe/constructor Яндекс.Карт загружаются автоматически,
без кнопки «Показать карту» и независимо от Analytics consent, включая Reject.
Не меняйте размеры/настройки и не добавляйте второй экземпляр карты.
Основная Метрика, включённая в ITD Cookies, остаётся под Analytics consent.

Не регистрируйте map handles в consent-gated Script Adapters и не связывайте
вывод карты с `ITDCookies.allowed('analytics')`. Если это делает интеграция темы,
исправлять нужно её после backup/local QA. Текущий runtime уже оставляет обычные
карты самостоятельными; настройки «разрешить карты» в ITD Cookies нет и не требуется.

Внешняя карта может передавать данные, использовать свои cookies/storage и
аналитику до согласия и после отказа. Это отдельно от основной Метрики сайта.
Не объявляйте карту технически необходимым cookie-сервисом ради обхода согласия.
Проверьте сведения в баннере/политике с владельцем: это правило поведения,
не подтверждение юридического соответствия. Generated Cookie Policy не заменяет
инвентаризацию внешних сервисов темы/iframe.

[Полное правило и admin-информация 0.4.4](MAPS-INTEGRATION-POLICY.md).
Изменение включено в общий typography/footer этап0.4.4, отдельный релиз не создаётся.

## Проверка перед rollout

- Новый посетитель/отказ: собственных optional SDK запросов нет в Network.
- Analytics/Marketing отдельно, all, save/reopen, reload/revoke: категории
  сохранены и соответствуют Network. Vendor delivery требует отдельной проверки
  с владельцем аккаунта; synthetic IDs для QA не подтверждают отчёты vendor.
- Проверяйте отсутствие повторных SDK инициализаций, исключая внутренние
  дополнительные запросы самого SDK; сверяйте Console/PHP logs.
- Desktop и 390/320 px: видимые controls, контраст на реальной теме, keyboard
  Tab/Escape/focus return, доступные действия при длинной панели.
- Updater показывает только настоящий stable GitHub asset; настройки/marker/
  consent/policy после upgrade сохранены. [Rollout checklist](PRODUCTION-ROLLOUT.md).

ITD Cookies **не универсальный script firewall**: произвольные трекеры themes/
plugins не блокируются автоматически. Script Adapters контролируют только
явно зарегистрированные закрытые группы классических WordPress handles.
Descriptive service registry entry сама по себе скрипт не блокирует.

## Изменения 0.4.3

Опубликованная и локально принятая stable — 0.4.3. Production rollout требует отдельного разрешения владельца.
Основная проверяемая линия начинается с WP 5.3 / PHP 7.4; новые production сайты
должны использовать актуальный Core и PHP с security support. WP 5.0–5.2
не включены в официальную матрицу поддерживаемых сочетаний. Тесты WP 5.2 /
PHP 7.4 — только регрессионный контроль существующих установок.

Metadata и runtime guard WP 5.2 сохранены: немедленное повышение до 5.3
отключило бы действующий consent engine на WP 5.2. Рекомендация владельцу:
сначала мигрировать эти сайты на поддерживаемые Core/PHP и отдельно согласовать
повышение floor. PHP 7.4 — EOL минимум совместимости, не рекомендация безопасности.

На отказавшем bootstrap consent API отсутствует. Интеграция должна проверять
function_exists('itd_cookies_allowed'); отсутствие API не означает согласие.
На WP ниже 5.8 версия 0.4.3 проверяет собственные update records при сохранении
и чтении: только canonical stable GitHub asset доверен. При ошибке GitHub
чужая запись того же basename удаляется, остальные плагины не изменяются.
Details modal возвращает WP_Error вместо fallback на каталог WordPress.org.
Это не защита от произвольного стороннего кода, который обходит Core updater.

Для 0.4.0/0.4.1 старый updater может ждать истечения шестичасового metadata cache.
Проверка снова в этих версиях не гарантирует немедленного сброса GitHub cache.
При необходимости используйте официальный опубликованный ZIP через штатный
Upload/Replace на WP >=5.5. На старом Core сначала предпочтительно обновить Core;
assisted file recovery выполняет администратор по проверенному backup.
Не удаляйте плагин через uninstall ради обновления: это может удалить настройки.
Assisted recovery не считать автоматическим обновлением.

Не запускайте два consent engines. До включения провайдера проверьте theme,
MU plugins, snippets и GTM на уже встроенный SDK; отключение одной интеграции
не удаляет чужой tracking code. Rollback файлов не требует слепого возврата
устаревшей production БД с потерей новых данных. [Приёмка релиза](ITD-COOKIES-0.4.3.md).


Stable v0.4.4: [официальный Release](https://github.com/itdream24/itd-cookies/releases/tag/v0.4.4), built asset `itd-cookies-0.4.4.zip`, SHA-256 `09d9ddb4a6b03f13d83875cff1c1cf657f5842a5d9d97683ef09dc8dc654c06d`. Реальное native обновление с 0.4.2 и новый immutable baseline проверены локально; production не изменялся. При обнаружении дефекта после публикации готовится отдельный patch release, опубликованные assets не перезаписываются.

## Rollout 0.4.5

Целевой пакет: `itd-cookies-0.4.5.zip` из Release `v0.4.5`, с отдельным SHA-256.
До установки сохраните настройки, Cookie Policy, marker, файлы и БД.
После native upgrade обязательно очистите WordPress page cache, CDN и asset cache.
Повторяйте purge после включения/отключения сервиса, смены его ID/privacy options
или consent_revision. До purge старый статический HTML отражает старый состав;
плагин не может переписать сторонний кеш и не меняет shared HTML по cookie.
Проверьте две чистые сессии: старый Reject не вызывает новый запрос согласия;
старый Accept all блокирует необязательные SDK до явного нового выбора.
Самостоятельные запросы карт не относятся к основной Метрике ITD Cookies.
Публикация и фактическая локальная проверка фиксируются в ITD-COOKIES-0.4.5.md.
